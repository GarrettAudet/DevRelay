# Project reports dynamically from registered record contracts

## Status

Proposed

## Context and problem statement

DevRelay needs human-readable run observability and repeating ready-frontier execution without transferring workflow authority to reporting, telemetry, or a mutable scheduler.

## Decision drivers

- Determinism
- Human readability
- Provider neutrality
- Traceability
- Privacy

## Considered options

- OPT-RUN-RECORD-DRIVEN-PROJECTION
- OPT-RUN-MODULE-SPECIFIC-RENDERER

## Decision outcome

Chosen: OPT-RUN-RECORD-DRIVEN-PROJECTION. The selected boundary preserves canonical DevRelay authority while making operational evidence inspectable and comparable.

## Consequences

- Positive: arbitrary circuits remain observable without module-specific renderer branches.
- Negative: structured contracts, content policy, and conformance evidence are required before WorkBreakdown.
