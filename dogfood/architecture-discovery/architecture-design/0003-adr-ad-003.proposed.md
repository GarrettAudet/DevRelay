# Block only material gaps and preserve all other uncertainty

## Status

Proposed

## Context and problem statement

DevRelay needs trustworthy current-system evidence before designing an existing repository while keeping inventory and analyzer capabilities replaceable and bounded.

## Decision drivers

- Determinism
- Source provenance
- Provider neutrality
- Least authority
- Privacy
- Verifiability

## Considered options

- OPT-AD-MATERIALITY-GATE
- OPT-AD-BLOCK-ALL-UNKNOWN

## Decision outcome

Chosen: OPT-AD-MATERIALITY-GATE. The selected boundary preserves Core routing, validation, confidence, Gate, and traceability authority while keeping repository observation capabilities replaceable.

## Consequences

- Positive: native and specialized analyzers can evolve without changing CurrentArchitectureSnapshot semantics or confusing inference with approved design.
- Negative: every binding requires version-pinned configuration, explicit repository scope, host-enforced permissions, provenance, and conformance evidence.
