# Keep current-state discovery observational and separate from intended architecture

## Status

Proposed

## Context and problem statement

DevRelay needs trustworthy current-system evidence before designing an existing repository while keeping inventory and analyzer capabilities replaceable and bounded.

## Decision drivers

- Determinism
- Source provenance
- Provider neutrality
- Least authority
- Privacy
- Verifiability

## Considered options

- OPT-AD-SNAPSHOT-NOT-BASELINE
- OPT-AD-DISCOVERY-PROMOTES-ARCHITECTURE

## Decision outcome

Chosen: OPT-AD-SNAPSHOT-NOT-BASELINE. The selected boundary preserves Core routing, validation, confidence, Gate, and traceability authority while keeping repository observation capabilities replaceable.

## Consequences

- Positive: native and specialized analyzers can evolve without changing CurrentArchitectureSnapshot semantics or confusing inference with approved design.
- Negative: every binding requires version-pinned configuration, explicit repository scope, host-enforced permissions, provenance, and conformance evidence.
