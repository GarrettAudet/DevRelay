## Implementation and acceptance after planning

Native executor registration, exact pins and artifact bytes, capability/grant
ceilings, adapter step normalization, typed handoffs, downstream Gates, trusted
contributors and durable resolved configuration remain runtime obligations.
Native selections must fail before effects if no exact registered executor is
available; no agent fallback is permitted. Active v1 runs retain their original
configuration. Swapping to v2 requires an explicit successor run and complete
preflight. Prove both unchanged v1 execution and real native v2 execution,
including tampering, stale lineage, missing capability, checkpoint interruption
and zero-effect replay, before claiming the module is usable.

The installed Desktop product still needs its versioned existing-project context
handoffs. Construction calls to owning runtimes do not establish that product
flow or complete the user's modular engineering vision.
