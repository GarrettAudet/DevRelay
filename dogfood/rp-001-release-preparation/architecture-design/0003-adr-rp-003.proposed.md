# Ship native Node and Windows release capabilities behind capability-oriented optional adapter slots

## Status

Proposed

## Context and Problem Statement

DevRelay must deepen live provider integration, evidence quality, requirements closure, queryability, and the ChatGPT Desktop on Windows path without transferring lifecycle authority to an adapter, skill, MCP server, domain pack, or external workflow.

## Decision Drivers

- Determinism
- Provider and domain neutrality
- Least privilege and local evidence
- Traceability
- ChatGPT Desktop on Windows compatibility

## Considered Options

- OPT-RP-NATIVE-PLUS-CAPABILITIES
- OPT-RP-HOSTED-PRODUCT-CORE

## Decision Outcome

Chosen option: "OPT-RP-NATIVE-PLUS-CAPABILITIES", because it preserves the approved authority boundary. The selected boundary preserves Core-owned routing, closure, validation, checkpointing, traceability, and Gate authority while allowing bounded best-in-class capabilities to be swapped.

### Consequences

* Good, because live capabilities become version-pinned, receipt-backed, replaceable, and auditable.
* Bad, because every provider and optional pack requires explicit acquisition, conformance, permission, failure-path, and Desktop evidence before a live maturity claim.
