# Use Codex task and A2A bindings behind one executor port

## Status

Proposed

## Context and problem statement

DevRelay needs replaceable executors without transferring readiness, binding validation, host enforcement, verification, integration, traceability, or promotion authority to executor adapters.

## Decision drivers

- Determinism
- One-item isolation
- Provider neutrality
- Least authority
- Traceability
- Verifiability

## Considered options

- OPT-WE-PORTABLE-EXECUTOR-PORT
- OPT-WE-PROVIDER-BRANCHES-IN-CORE

## Decision outcome

Chosen: OPT-WE-PORTABLE-EXECUTOR-PORT. The selected boundary preserves canonical DevRelay authority while keeping concrete executors replaceable, bounded, and auditable.

## Consequences

- Positive: Codex tasks, A2A agents, humans, and future executors can implement the same execution-attempt port.
- Negative: every concrete binding requires version-pinned configuration, declared authority, host enforcement, and conformance evidence before invocation.
