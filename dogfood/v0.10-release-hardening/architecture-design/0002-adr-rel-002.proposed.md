# Separate release evidence from host-enforced GitHub promotion

## Status

Proposed

## Context and problem statement

DevRelay needs a deterministic GitHub-only source/library release path whose installed Windows behavior, governance, evidence, and host promotion are explicit without transferring lifecycle authority to release tooling.

## Decision drivers

- Determinism
- Installed-consumer correctness
- Provider neutrality
- Traceability
- Windows compatibility

## Considered options

- OPT-REL-EVIDENCE-THEN-PROMOTION
- OPT-REL-TOOLING-SELF-APPROVES

## Decision outcome

Chosen: OPT-REL-EVIDENCE-THEN-PROMOTION. The selected boundary keeps package exports canonical, separates evidence from host-enforced GitHub effects, and preserves DevRelay Gate authority.

## Consequences

- Positive: the exact tarball can be reproduced and verified from GitHub source on the release-defining Windows matrix.
- Negative: structured contracts, installed-package evidence, and protected-main evidence are required before release promotion.
