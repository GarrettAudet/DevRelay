# DevRelay Godot Release

1. Load the approved requirements, architecture, contracts, work DAG, assignment, and current repository snapshot.
2. Require an exact supported Godot, GdUnit4, Godot AI, Windows, and architecture tuple from the compatibility policy. Stop if unavailable or unattested.
3. Require explicit capability grants for every Godot MCP operation. Record scene inspection, input simulation, screenshots, execution, and logs as exact receipts.
4. Run the pinned GdUnit4 adapter for required focused, full, scene, fuzz, flake, soak, JUnit, export, and smoke stages. Preserve stdout, stderr, exit code, duration, tool versions, command fingerprint, JUnit XML, and artifacts.
5. Submit evidence to WorkItemVerification. Do not interpret console prose as approval.
6. Integrate only verified changes through ChangeIntegration.
7. Run SystemVerification over the integrated Godot build.
8. Create the implementation seal, then a direct-child evidence seal that binds exact receipts without self-reference.
9. Stop on version drift, missing grant, flaky or failing evidence, export mismatch, dirty worktree, ancestry mismatch, or missing BusinessAcceptance.

This skill coordinates released operations only. It cannot approve Gates, integrate changes, or authorize a release; Core and the owner retain that authority.
